# ЕМИАС

Симулятор государственной медицинской информационно-аналитической системы
для ролевой игры в Discord.

> **Дисклеймер.** Это вымышленный симулятор для ролевой игры. Проект не имеет
> отношения к Минздраву РФ и реальной системе ЕМИАС. Все данные, пациенты и
> врачи — вымышлены.

## Архитектура

Трёхслойная гибридная модель: веб-панель + API-шлюз + Discord-бот (фаза 2),
все компоненты работают с общей базой данных через API.

```
┌─────────────────┐     ┌──────────────────────┐     ┌─────────────────┐
│  Веб-панель      │◄───►│  API-шлюз             │◄───►│  Discord-бот    │
│  web/ (HTML/CSS/ │HTTP │  server/ (Express,    │ WS  │  bot/ (фаза 2)  │
│  JS, Golos Text) │REST │  node:sqlite, ws)     │ REST│                 │
└─────────────────┘     └──────────┬───────────┘     └─────────────────┘
                                   │
                          ┌────────▼────────┐
                          │  SQLite          │
                          │  data/emias.db   │
                          └─────────────────┘
```

- **API-шлюз** — единственная точка доступа к данным (никаких прямых
  обращений клиентов к БД). REST `/api/*`, WebSocket `/ws`, статика `web/`.
- **Веб-панель** — портал персонала: очередь, расписание, пациенты, ЭМК,
  аналитика. Обновления real-time по WebSocket.
- **Discord-бот (фаза 2)** — равноправный клиент того же API; заготовка и
  правила интеграции описаны в `bot/README.md`.

## Быстрый старт

Требуется Node.js ≥ 22.5 (встроенный модуль `node:sqlite`).

```bash
npm install
cp .env.example .env        # заполнить при необходимости
npm run db:migrate          # создать схему БД
npm run db:seed             # демо-данные (опционально)
npm start                   # http://localhost:3000
```

Для локальной разработки без настроенного OAuth2 в `.env` включён
`DEV_LOGIN=1` — на странице входа появится кнопка автовхода демо-сотрудником.
На сервере используйте `NODE_ENV=production`.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `PORT` | порт API-шлюза (3000) |
| `PUBLIC_BASE_URL` | публичный URL (для redirect_uri OAuth2) |
| `DB_PATH` | путь к файлу SQLite |
| `DISCORD_CLIENT_ID` / `DISCORD_CLIENT_SECRET` | приложение Discord (OAuth2, scope `identify`) |
| `ADMIN_DISCORD_IDS` | Discord ID через запятую → роль «Главный врач» |
| `DEV_LOGIN` | автовход без OAuth2 (только вне production) |

Redirect URI в Discord Developer Portal → OAuth2: `{PUBLIC_BASE_URL}/auth/callback`.

## Структура

```
server/            API-шлюз (Express + node:sqlite + ws)
  auth/            Discord OAuth2 (state + PKCE), cookie-сессии
  middleware/      requireAuth / RBAC (права проверяются только здесь)
  routes/          auth, patients+ЭМК, appointments(очередь), staff/stats/audit
  realtime/hub.js  WebSocket-хаб (broadcast событий)
  db/              подключение, миграции, сид
shared/            общие константы и словари (МКБ-10, статусы, события)
web/               веб-панель персонала (ванильные HTML/CSS/JS)
bot/               фаза 2: Discord-бот как клиент API
data/              emias.db (вне репозитория)
```

## Стандарт проекта (кратко)

- Единая БД; доступ к данным — только через API-шлюз.
- WebSocket для критичных обновлений (очередь, статусы врачей).
- Вход — Discord OAuth2 (`identify`, state + PKCE); секреты — только в `.env`.
- Палитра `#0063B0 / #F5F7FA / #0066CC`, шрифт Golos Text.
- Документы (ЭМК, рецепты) — стилизованные «бланки» с шапкой, полями,
  футером-реквизитами и маркировкой «ЕМИАС».
- Дисклеймер на странице входа и в подвале всех экранов.
- RBAC: врач видит медданные только своих пациентов; регистратор — демографию;
  «Главный врач» — аналитику и журнал аудита.
- Журнал аудита значимых действий (кто / когда / что).
